## 2. The console

The console is the shell that frames the sixteen dashboards: a spine of wings and atlases, a command bar with breadcrumbs, a hash router, a command palette, one theme carried into every framed dashboard, and three views of its own (Command Deck, Convergence, Agency Field) computed from a data block compiled with the atlases. The browser app adds a fourth view, the Résumé Forge, through anchored patches. Console version 1.2.0; data block compiled 2026-10-06; Agency Radar compiled 2026-09-29; Horus edition 2026.09a run 2026-09-27.

### Page shell and boot

A single HTML file with three font families embedded (IBM Plex Sans, IBM Plex Mono, Zilla Slab, 15 font faces under the SIL OFL), an SVG favicon, a noindex robots meta, viewport safe area insets and reduced motion respected. A "Starting Leviathan" notice is replaced once the script boots. Boot order: host theme watch, theme, spine, bar, palette, downloads, then the first route. window.__LV_CONSOLE exposes live, open, go, prefs and the version 1.2.0.

### Spine and navigation by wing

A fixed dark spine on the left carries the brand mark, the Command Deck, the Core group (OmegaWeapon, Hit Board), one group per wing whose header opens the wing view and whose items are the atlases, and an Across industries group (Convergence, Agency Field, and Résumé Forge when patched). The active atlas unfolds a sub list of its modules grouped Market, Practice, Campaign, Content and Method.

- Live dots on each dashboard item: green when live, pulsing gold while opening.
- aria-current on the active wing, atlas and module; the list scrolls to keep the active item in view.
- The spine collapses or shows from the command bar (remembered in preferences); on screens under 900 px it becomes a drawer with a scrim.
- The spine foot reads "Build <date> · 16 dashboards" and "Atlases open on demand. The five most recent stay live."

### Command bar and breadcrumbs

A slim bar above the working surface holds the spine toggle, breadcrumbs, the search button, the Module cards toggle and the theme switch. The crumbs read Core / OmegaWeapon / view (naming Agency dossier or Target for those Core routes), Core / Hit Board / module, Wing / vertical / atlas / numbered module, or the console view, with a color chip for the wing. The document title follows the last crumb, as in "Convergence · Leviathan". On narrow screens only the current crumb shows; under 1100 px the bar hides its labels.

### Routes and hash deep links

The hash is the route: command, a wing (legal, home, health), convergence or convergence.<ZIP>, agencies or agencies.<wing or vertical key>, resume or resume.<agencyId> when patched, a dashboard id, or dashboard.module (for example hvac.paid or core.pulse). Core routes carry slashes as tildes (core.a.<id> for a dossier). An unknown hash falls back to the Command Deck.

- A module change inside a live dashboard is mirrored into the hash with replaceState, so the URL is always shareable.
- A ZIP picked on the Convergence map rewrites the hash to convergence.<ZIP>.

### Command palette (Ctrl K)

A modal search opened by Ctrl K (Command K on a Mac), the slash key or the bar's search button. With no query it lists the console views and the dashboards. A query searches five groups: Console (views and wings), Dashboards, Modules (with their numbers), Agencies (the 222 in the index, opening the Core dossier) and ZIP codes (the 2,528 scored ZIPs, matched by ZIP or city and ranked by population, opening Convergence). Results are grouped, at most 8 per group and 12 ZIPs, ordered by the best match in each group. Arrow keys move, Enter opens, Escape or a click on the backdrop closes.

### Theme (Auto, Light, Dark)

A three way switch in the bar. Auto follows the system setting; Light and Dark stamp data-theme on the root, and the CSS defines the dark tokens both under prefers-color-scheme and under :root[data-theme=dark]. The choice is saved in preferences and pushed to every live dashboard; a dashboard's own toggle is carried back to the console and the other live dashboards, and a viewer that stamps data-theme on the root is followed too.

### Module cards toggle

A bar button, shown when an atlas (not the Core) is on screen on a wide window, switches between the console's spine listing an atlas's modules and the atlas showing its own module cards. The preference is remembered and applied to every live atlas.

### Module host: atlases on demand, five live

Each dashboard is a gzip payload unpacked in the browser with DecompressionStream when first opened. Twelve payloads sit inline in the page, four load from two companion scripts fetched only when needed, and a third path fetches m/<id>.txt for a split folder layout. A loading card shows "Unpacking N MB" then "Starting <atlas> · N modules". The five most recently opened dashboards stay live (MAX_LIVE 5) and the least recent is unloaded beyond that. An atlas that has not registered within 90 seconds, or whose payload is missing, shows an error card with Try again and a Command Deck link.

- One srcdoc iframe per live dashboard on a stage; console views and the stage swap visibility.
- A pending route (module key and payload) is handed to the dashboard once it registers.

### Host link for framed dashboards

The console exposes window.__LEVIATHAN to its iframes with ten members: theme(), framed(), canSave(), save(), railHidden(id), initialRoute(id), register(id, api), moduleChanged(id, key), moduleTheme(id, t) and navigate(tok). On register the console pushes the theme, hides the atlas's own rail while the spine is shown (except for the Core), applies the pending route, and thereafter drives the dashboard through api.go, api.setTheme and api.rail while reading api.current and api.route for the crumbs and the hash. In the browser app the bridge turns these direct calls into postMessage traffic.

### Command Deck (home)

The console home at #command. A masthead carries the build date and the Radar, Horus and atlas compile dates, followed by six tiles, a Core card, one card grid per wing, an Across industries section and a provenance panel.

| Element | What it shows |
|---|---|
| Tiles | Atlases, ZIP codes (Texas and Louisiana split), National ZIPs or Counties, Agencies with deep dossier count, Competitors plus oncology clinicians, Modules |
| Core card | Radar regions, Horus edition and run date, the twelve Core views as links, a Hit Board kill order block (top three, link to all ten), Where the field invests (top eight of fifteen strategy shares), Horus key judgments with likelihood and range |
| Atlas cards | One per dashboard in each wing: headline A+ ZIPs or ZIPs scored, fact chips, top ZIPs per state with atlas index and bid tier, module count and compile date |
| Across industries | Texas and Louisiana convergence leaders with one correlation sentence each, and Agency Field vertical bars |
| Provenance | Sources and build notes for all sixteen dashboards, with each dashboard's footnotes |

Actions: open the Core, the Hit Board, the Agency Field, a wing, an atlas or a Core view; any top ZIP links into Convergence at that ZIP.

### Wing views (Legal, Home services, Healthcare)

One view per industry wing at #legal, #home and #health. Each shows the wing's dek, a full atlas card for each atlas (sub line, eight facts, bid tier bar, top three ZIPs, quick links to the index, paid, desk, forge, watch, field and lines modules), a per state convergence block for the wing's verticals (eight leaders per state with correlation sentences, or a note when only one vertical covers the state), and the top 14 agencies selling into the wing with a link to the full Agency Field. Actions: open the wing in Convergence with the lens preset, or open the Agency Field filtered to the wing.

### Convergence map

The cross industry view at #convergence lines up every atlas's ZIP ranking on one Texas and Louisiana choropleth so a reader can see where several verticals run hot in the same ZIPs. Controls pick the state, a lens by wing or by vertical, the score (mean state percentile or hot count) and a population floor.

| Element | What it shows |
|---|---|
| Choropleth | SVG map of ZIP shapes with county lines, state outline, water and place labels that hide when they collide; a seven class legend for mean percentile or a 0 to 5+ legend for hot count |
| Side card | The leaders in the lens, or the selected ZIP's stack per vertical with state percentile, atlas index, bid tier, model volume and dollar pool |
| Ranked ZIPs table | Sortable by any column, top 60 or all |
| Correlation matrix | Spearman correlations per state with a five step diverging legend and insight sentences |
| Method panel | How Convergence scores a ZIP: state percentile, mean percentile, hot count, inclusion and correlation |

Actions: toggle Texas or Louisiana, choose a wing lens or single verticals, switch mean percentile and hot count, skip ZIPs under 1,000 residents; zoom in, zoom out, fit the state, wheel zoom, drag to pan, hover for a tooltip, click a ZIP or a table row to select it; open the selected ZIP in any atlas with the ZIP (and the state for a national atlas) handed to that atlas's index or paid module. Export: a CSV of the ranked ZIPs (leviathan-convergence-tx.csv or -la.csv) with place, residents, lens, mean percentile, hot count and every vertical's percentile, index and tier.

### Agency Field

The view at #agencies lists the Radar agencies that publish client verticals reaching into the three wings: three wing cards with agency counts per vertical (each bar a link to agencies.<vertical>), a filter row and a sortable table. Table columns: Agency (with domain, headquarters and archetype, and a Hit Board wave tag when marked), Verticals as pills, Local, SEO and Paid search on a three dot scale, Google ads seen in 30 days, Monsoon offshoring index, Horus tailwind index and band, Prominence. The masthead notes the thinnest specialist fields and where the verticals and indexes come from. Actions: filter by wing (All, Legal, Home services, Healthcare), by one vertical, Specialists only, or by typed agency, domain or vertical; sort by agency, verticals, local, SEO, ads, Monsoon, Horus or prominence; open an agency's dossier in the Core (core.a.<id>) or the Hit Board's ten (hitboard.ten); a Résumé link on every row when the browser app's patch is present.

### Cross industry scoring layer

The only numbers the console computes itself: for a state and a set of verticals, each ZIP's mean state percentile (ranked only when at least 60 percent of the lens scores it), its hot count (verticals placing it in the state top fifth), the leaders, and Spearman correlations between vertical pairs. The Command Deck, the wing views and Convergence all draw from it.

### Tooltips, toasts, downloads and keyboard

- A shared positioned tooltip (title plus label and value rows) serves the map, the correlation cells and other hover targets; a bottom toast with a polite live region reports saves, copies and errors.
- saveFile saves through a host downloads capability when a viewer offers one, otherwise through a blob link in the page; when the console is framed as a viewer, downloads are off and text files are copied to the clipboard instead. Files handed over by a dashboard document are rebuilt in the console's realm before saving. The browser app patch makes isFramed answer false so downloads stay on inside the extension. Exports: the Convergence CSV and any file a framed dashboard hands up through host.save.
- Keyboard: Ctrl K or Command K and the slash key open the palette (the bar shows ⌘K on Apple platforms), Escape closes the palette or the spine drawer, arrow keys with Enter drive the palette; the map takes wheel zoom and pointer drag, and table headers sort on click.

### Console wide features

- Everything runs in the browser from one page plus two optional companion scripts; nothing is sent anywhere.
- Preferences (theme, module cards, spine) are per viewer and never load bearing; in the extension they go through the bridge to extension storage.
- The console is brand neutral and computes only the cross industry layer; each dashboard keeps its own data, models and brand settings.
- Responsive: the spine becomes a drawer under 900 px, the bar hides labels under 1100 px.
- Accessible markup: aria-current navigation, labelled controls, a role dialog palette with a listbox, live regions for the loader and the toast, focus outlines.

### The console's data block

The lv-data block (compiled 2026-10-06) holds: modules (16 dashboards with facts, module lists, top ZIPs, tiers, compile dates and footnotes), verts (14 verticals with states, index labels, volume and value labels), conv (2,528 ZIPs with state, city, county, population and per vertical percentile, index, tier, volume and value), corr (Spearman matrices for Texas and Louisiana), geo (2,518 ZIP shapes, 318 county shapes, outline, water and 53 place labels on a 4800 by 3414 map frame), wings and ext (the companion script map). Core context in the block: Agency Radar generated 2026-09-29 (222 agencies, 110 deep, 110 US and 112 Europe), Horus edition 2026.09a run 2026-09-27, 15 strategy dimensions, 8 key judgments, 10 Hit Board targets, OmegaWeapon 2.0.0. agencyIndex (222 agencies: id, name, domain, region, archetype, Hit Board wave) feeds the palette; agencies (115 with published verticals, strategy levels, ads seen, Monsoon, Horus, prominence) feeds the Agency Field. Dashboard facts cite cancer registry rates, ads transparency captures, licensing counts and each atlas's own paid model; no keyword or backlink data was pulled for the build.

### Console caveats

- The m/<id>.txt fetch path is a third loading path for a split folder layout; this build ships no m/ folder, so only the inline payloads and the two companion scripts are used.
- The host downloads capability is used only when a viewer provides window.claude; inside the extension the blob download path runs.
- Counts of agencies, ZIPs and modules come from the data block, not from unpacking the dashboards.
- The Résumé Forge route, spine item, crumbs, palette entry and view hook are present only in consoles the browser app's build has patched; the upstream frame script does not carry them.

**Dashboard wide features.**

- Masthead brand mark with edition and target count; document title Agency Radar.
- Global search across targets, agencies and clients with a slash keyboard shortcut.
- Theme button cycling system, light and dark, synced with the Leviathan console host.
- Tab rail of the 12 views with Watchlist and Compare count badges.

- Sortable tables, tooltips, toasts, HTML bar charts with SVG where geometry demands it.

**Caveats.**

- The index maps aging plumbing and the conditions that break it, not service calls; no agency counts plumbing repairs, and it is not a claim about any one house or a media plan.
- Only three things are fitted to observed outcomes (water heater lifetimes to RECS 2020, the freeze damage function to Texas Uri claims, permit regressions to Austin permits); everything else is a stated assumption with a grade.
- Replacement, repipe, cast iron and lateral counts come from renewal models on the housing stock, none is a count of jobs anybody reported; pipe materials are priors by build year.
- Permits capture a small share of work; Uri claims are the only public plumbing claim file by ZIP; FEMA aid counts applicants and NFIP counts policyholders only.
- Click cost and conversion are national benchmarks (grade C) and search volume is an order of magnitude assumption (grade D); no keyword tool was queried and no Ahrefs units were spent.
- Three plumber counts have three denominators: TSBPE licensees, Census establishments (HVAC included) and a thin Louisiana field, because the Louisiana roster allows verification only.
- The competitive field is the licensed field; no reviews, domain ratings or ad spend were pulled, and silence in the ad libraries is not evidence.
- County data is spread to ZIPs, ACS is a survey with sampling error, and the Louisiana freeze check is out of sample.
- Weather bid plans are bid schedules, not a forecast of calls; inside the viewer the desk shows a baked snapshot.
- The Campaign Desk and Site Forge connect to no platform, never publish on their own and export every object paused; deploying from the hosted atlas is blocked by the viewer's network rules.
- Slab leaks and sewer failures have no public count; the atlas uses soil, drought, slab and build year exposure instead.

### Where the draft is stored

One draft object (version 2) holds the candidate's facts shared across agencies, a tailoring per agency (track or industry, title, summary, added terms, pasted posting), a general tailoring and the last agency, saved under the key resume in the bridge store 250 ms after input and flushed on change, focus out, tab hide and page hide. Inside the extension the bridge posts it to app.js, which keeps it under leviathan.store.v1 in chrome.storage.local; outside the wrapper the bridge's fallback keeps the same key in localStorage, and a stored or imported draft is normalized to the draft shape before it draws.

### Data sources

### Caveats

- Findings are model based reads of each agency's public record on the compile date shown; the Forge says on screen and in the brief that the agency may not be hiring for the track.
- The generated findings script is about 1.27 MB on disk, above the 600 KB target in the design notes; it loads lazily as one string so the console's start does not pay for it.
- The design notes predate the engine in places: they describe twelve tracks ranked by a severity sum and keyword coverage inside the lint, where the shipped engine has seventeen tracks ranked on demand and angle with rarity weights and a separate mirror readout. A keyword coverage check inside the lint, a no tabs or pipes check, a founder led ownership rule, a LinkedIn ads while selling B2B finding and the twelve track severity sum ranking exist only in the design notes, not in the shipped engine.
- Hit Board hiring themes are a hand curated table per target in the build script; a target absent from it ships placement only.
- The ATS standards are stated in aggregate; no ATS vendor is named or profiled.
- Verticals and atlas links cover three wings only (legal, home services, healthcare); the contact check recognises US city state pairs, a short list of cities and the word remote, and non US agencies get a conventions note only.
- The draft is per device; export and import of the JSON file is the only way to move it.

## 6. The browser app

A Manifest V3 extension for Chrome, Edge, Brave and other Chromium browsers that ships the console as a sandboxed page, frames it from a wrapper page that keeps its preferences, recents and the Résumé Forge draft in extension storage, launches it from a popup, the address bar and a keyboard command, and is rebuilt from the Leviathan repository by a build that patches the console with anchored one line edits, scrubs withheld names, validates, tests and zips. App 1.1.0 built 2026-10-07 around console 1.2.0 compiled 2026-10-06.

**Headline counts.** App 1.1.0 (manifest and EXT_VERSION), console 1.2.0, registry built 2026-10-07; registry of 16 dashboards in 4 groups (Core 2, Legal 6, Home services 5, Healthcare 3) and 4 console views; 1 permission (storage), 1 sandboxed page, 1 omnibox keyword (lev), 1 command (Ctrl+Shift+L, Command+Shift+L on a Mac); 13 anchored patches (6 carry the app, 7 carry the Résumé Forge) and 16 markers each expected exactly once; 4 ext scripts beside the console (host-bridge, resume-findings, resume-engine, resume-forge), inlined by the single file edition; 4 encoded entries on the withheld list, one matched as a whole word; 8 unit test files; 47 end to end checks and 3 screenshots; recents of 8 kept in storage and 6 shown in the popup; popup search up to 14 rows, omnibox up to 6; icons at 16, 32, 48 and 128 pixels.

### Popup launcher

The toolbar popup (380 px, light and dark by system setting): a header with the mark and "N dashboards · N wings", a search box over atlases and modules, the four console views as buttons (the first primary), Recent chips, and the wings with one row per atlas (wing color dot, spine title, subtitle). Enter opens the first match, Escape clears, arrow keys move between rows. A footer line carries the console version, compile date and app version; search rows for modules show the atlas id as a key. A view, an atlas, a module or a recent atlas opens in the existing console tab, or in a new tab when the "Open in a new tab" switch is on (remembered in leviathan.popup.v1).

### Omnibox keyword and keyboard command

Typing lev, a space and an atlas or module name in the address bar suggests up to six matches (title and subtitle) with a default "Leviathan: open <match>" suggestion; Enter opens the resolved route in the current tab or a new one by disposition. The open-console command, Ctrl+Shift+L or Command+Shift+L and changeable at chrome://extensions/shortcuts, opens or focuses the console.

### Wrapper page (app.html, app.js)

An ordinary extension page frames the sandboxed console edge to edge with clipboard write and fullscreen allowed, and paints the console's ground color before the first frame. It reads the preferences from chrome.storage.local and hands them to the console in a ?lvp= query string with the tab's hash as the first route, saves preferences the console posts back, mirrors the console's route into the tab URL with replaceState, records recently opened atlases (up to eight), keeps the store snapshot for the scripts beside the console (one key at a time, writes serialized), and answers where and go messages from the popup, the omnibox and the command. Storage keys: leviathan.prefs.v1, leviathan.recent.v1, leviathan.store.v1. A hash typed, bookmarked or set by the popup is handed to the console as a go message; on the console's ready signal (its first route) the whole store snapshot is posted into the frame.

### Background service worker and open helper

The worker imports registry.js and open.js, opens the console in a new tab on first install, handles the open-console command, and serves the omnibox (default suggestion, suggestions on input, the route on Enter). The open helper (open.js), shared by the popup and the worker, builds the openable entries from the registry (views, atlases titled as the spine shows them, modules as atlas.key), scores a search (prefix matches first, atlases above modules), resolves typed text to a route with the Command Deck as fallback, and opens a route by reusing the console tab that is already open (activating its tab and window and sending go) so its live atlases stay live, else in the current or a new tab.

### Host bridge and store (console/ext/host-bridge.js)

Loaded ahead of the console's frame script inside the sandbox. wrapAtlas plants a shim at the top of every atlas document before it is framed: the shim shadows window.parent with a stand in whose __LEVIATHAN answers theme, rail and initial route from a seed, posts register, moduleChanged, moduleTheme, navigate and save up, and takes setTheme, rail, go and brand down, answering each with a state snapshot. On the console side the bridge registers a proxy api per live atlas whose current() and route() read the last snapshot, so the console's own code runs unchanged.

- A second shim serves the module documents a shell atlas nests: the atlas hooks the srcdoc setter, plants it, and relays the theme to it; the inner document applies data-theme, dispatches themechange and hides the module masthead.
- Preferences load from the ?lvp= query and save by posting to the wrapper; the route is relayed on hashchange, replaceState and pushState with a ready flag on load.
- The store: one snapshot of the wrapper's storage, synchronous reads from a cache, writes posted per key, writes made before the snapshot held and posted after it (so a slow wrapper never overwrites a draft), onSnapshot listeners for a late snapshot, a 4 second settle fallback, and localStorage standing in outside the wrapper.
- window.__LV_EXT exposes version, loadPrefs, savePrefs, store, wrapAtlas and the shim sources.

### Sandbox CSP and permissions

Manifest V3 forbids inline scripts on extension pages, so console/Leviathan.html is declared a sandboxed page with its own CSP (sandbox allow-scripts allow-forms allow-popups allow-modals allow-downloads allow-popups-to-escape-sandbox; script-src self, unsafe-inline, unsafe-eval, blob and data), while the extension pages keep script-src self and object-src self. The only permission is storage; the build refuses tabs, history and all URL permissions and allow-same-origin. Firefox is not covered because it has no sandboxed extension pages.

### Registry (registry.js)

Generated by the build from the console's lv-data block and read by the popup, the omnibox, the wrapper and the tests: app and console versions, compile and build dates, the wings in console order with their atlases, each dashboard's id, wing, vertical, short and long titles, scope label, up to three facts, raw size and module list, the companion script map, and the four console views.

### Build (build.mjs) and its validation

Node 22, no packages. Without flags it rebuilds console/ and registry.js from ../leviathan when the console sits beside the folder (the Leviathan repository) and otherwise validates the folder, then runs the unit tests. Flags: --from <dir> takes a checkout (its root or leviathan/ folder); --fetch downloads Leviathan.html and the companions it names from GitHub (main, or --branch); --findings regenerates the Forge findings alone; --full writes the single file edition; --zip writes the install zip; --check validates only; --no-test skips the tests. A rebuild patches and scrubs the console, copies or scrubs the companion scripts, removes stale companions, regenerates the registry and the findings, and reports sizes; a moved anchor fails the build by name.

Validation steps: the manifest (v3, version format and EXT_VERSION match, named files exist, both CSPs, sandbox page listed, storage only); the extension pages (no inline scripts or handlers, scripts exist); the console (each marker once, bridge present, companions carry their payloads, registry.js in step, byte for byte in step with the source); the Résumé Forge files and findings (agencies match the agency index, field context present, Radar compile date in step, base rates present); the withheld scan of the whole repository; node --check on every script.

The install zip puts the app under one folder, leviathan-browser-app/, by default at ../dist/leviathan-extension.zip, skipping tests, lib, tools, dist and build.mjs; unzip and Load unpacked on that folder.

### Anchored patches and idempotent re patching (lib/patch.mjs)

Thirteen replacements, each anchored on text that must occur exactly once in the frame script: a version marker in the head, the four ext script tags before the frame script, srcdoc through wrapAtlas, isFramed answering false under the extension, the preference loader and saver going through the bridge, and for the Forge a spine entry after Agency Field, the resume route in the parser and the dispatcher, its crumbs naming the agency, a palette entry, a Résumé link on every Agency Field row and the viewResume hook. A console that already carries the marker is unpatched first (by shape for the version meta, the script tags or inline blocks and the view hook, by exact text for the rest), so a console or edition this build wrote earlier can be rebuilt in place; a patch this build does not know fails the unpatch loudly. The file also holds the registry extraction and a dependency free zip writer (stored or deflate, CRC32).

### Withheld name guard (lib/scrub.mjs)

A list of names that must never ship anywhere in the repository, kept base64 encoded so the names never appear in the repository text; an entry matches case insensitively with any whitespace or none between its words, and one marked entry matches as a whole word. A rebuild finds every gzip payload in the console and the companions, inflates it, drops the flat data rows that carry a name and re deflates the payload, failing when a name sits outside a row it can drop. The validation walks the whole repository, every text file, every zip entry (zip, skill, crx, jar, xlsx, docx, pptx) and every payload inflated, checks paths and entry names too, and refuses the build while a name remains, reporting file, entry, payload and offset but never the name.

### Single file edition (lib/full.mjs)

Built by --full from the repository's Leviathan-full.html, which carries every payload inline: the same patches and scrub, then the four ext scripts written inline in place of their script tags (closing tags escaped), checked so that every marker occurs once outside the inline blocks, each block once and no external script remains. It opens from disk, from a static host and inside the extension alike, Forge included; in the Leviathan repository it is written in place, elsewhere to ../dist/Leviathan-full.html or the file given, and --fetch --full downloads the source too.

### Findings extraction (lib/findings.mjs)

Build only: unpacks the OmegaWeapon and Hit Board payloads from the console, joins the Agency Field's vertical reach, and writes console/ext/resume-findings.js as one JSON string with one record per agency and the field context.

- **The registry and the popup.** registry.js, generated from the console's lv-data block, drives the popup launcher, the omnibox suggestions, the wrapper and the tests; the popup lists the four console views, the wings and their atlases, recents and a search over atlases and modules.
- **The single file edition.** lib/full.mjs produces Leviathan-full.html with every payload and the four ext scripts inline, so the Forge and the bridge work from a single file opened from disk or a static host as well as inside the extension.
- **The build, its validation and its tests.** build.mjs rebuilds the console from the Leviathan repository or a GitHub fetch with thirteen anchored, idempotent patches, regenerates the registry and the findings, validates the manifest, the pages, the console, the Forge files and the withheld scan, writes the install zip, and runs eight unit test files; the Playwright run checks the whole chain in 48 assertions.
